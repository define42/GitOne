01 — Executive summary

One structural weakness, seen from many angles

The five High-severity issues cluster around a single fact: GitOne is a single-process server with almost no backpressure, so any one unbounded operation — an unthrottled Argon2id/LDAP flood, a giant diff buffered in memory, a slowloris trickle, an exclusive lock held during a full-tree scan, or an unsandboxed build container — can degrade or take down every repository on the storage root.

The standout strengths are the disciplined per-request re-authorization model, deliberate Argon2id with fail-closed identity handling, and an SSRF allowlist on imports. That competence is exactly why the gaps read as unfinished hardening rather than design blindness — and why most of the fixes are additive and low-risk.

02 — What's already right

Strengths to preserve
  • Per-request authorization. Roles are re-evaluated against control.json on every request (auth.go:118), so revocation takes effect immediately even though sessions are stateless.
  • Strong password handling by design. Argon2id at m=19 MiB, t=2 (auth.go:19), fail-closed identity canonicalization, and proper ldap.EscapeFilter in the live path (ldap.go:242).
  • Rigorous merge gate. Distinct-author approval, resolved-thread checks, and exact-commit mergeability are all enforced at the merge choke point (reviews.go:901).
  • SSRF-aware imports. Loopback/private/link-local/metadata ranges are blocked with DNS-pinned dialing and per-redirect revalidation.
  • Data-format discipline. control.json is versioned v1→v4 with strict rejection of unknown versions; review records use DisallowUnknownFields.
  • The runner already shuts down gracefully via signal.NotifyContext — the exact pattern the web server is missing.
  • Streaming Git/LFS paths are protected by sliding read/write deadlines (httpio.Protect); the gap is only that this wasn't extended to the JSON API and UI.

03 — Findings

30 verified findings, most severe first

High severity

5 findings
H1Unthrottled auth → Argon2id/LDAP exhaustion & brute forceconfirmed
internal/httpapi/session.go:76 · also api.go:1095, server.go:44 · resource-exhaustion

No login, Basic-auth, or git/LFS path is rate-limited or locked out. Every unauthenticated request drives an LDAP bind, and guessing a group plus a human-readable token key (ci, deploy) forces a full ~19 MiB Argon2id per request. ~100–200 concurrent requests consume 2–4 GB and saturate cores; failed-login spraying exhausts LDAP and can lock out real users.

Fix Per-IP/per-user rate limiting with backoff before any bind/Argon2id call; a global semaphore bounding concurrent Argon2id; 429 on excess.
H2Commit-diff & branch-compare are unbounded and fully bufferedconfirmed
internal/httpapi/merge.go:547 · resource-exhaustion · reachable at RoleRead / anonymous on public repos

Each patch is clamped to 1 MiB but there is no file-count cap, and the whole structure plus its JSON is assembled before the first byte. A repo whose root commit adds ~30,000 large text files makes any reader's diff request allocate several GiB and OOM the shared process — killing every repo. A legitimate monorepo triggers the same crash by accident.

Fix Cap file count and aggregate patch bytes with a truncated flag, and/or stream the diff.
H3Runner claim holds a process-global exclusive lock during an O(all repos × all jobs) scanconfirmed
internal/runner/coordinator.go:131 · resource-exhaustion · jobs are never pruned

Claim takes the process-wide catalog lock Exclusive and, while holding it, walks the whole storage tree and unmarshals every historical job file. All git/LFS traffic takes that lock Shared, so it blocks for the full scan — re-run by every idle remote runner every 2 s. With no pruning, the window grows without bound: a self-inflicted DoS that worsens over time.

Fix Maintain a claimable-job index guarded only by the queue lock (O(pending)); add retention/pruning; return fast on idle polls; at minimum scan under a Shared lock.
H4Build containers run with no network isolation or resource limitsconfirmed
internal/runner/executor.go:63 · security · script/image come from repo .gitone.yaml

The docker argv sets no --network, --memory, --pids-limit, --cpus, --cap-drop, or --user. Any Developer who can push a matching branch controls the executed code — e.g. curl 169.254.169.254 to exfiltrate cloud IAM credentials, bypassing the very SSRF allowlist the import path enforces, or run a fork bomb.

Fix Default --network none (opt-in, admin-gated egress); always apply memory/pids/cpu limits, --cap-drop=ALL, no-new-privileges, non-root --user — non-overridable by repo config.
H5JSON API & UI have no active-request I/O deadline (unauthenticated slowloris)confirmed
cmd/gitone/main.go:99 · resource-exhaustion · same defect class already fixed for Git

Only ReadHeaderTimeout/IdleTimeout are set; the Huma API, SPA, and raw runner-source tarball get no per-request deadline and no TimeoutHandler. Trickle a JSON body to unauthenticated POST /api/session one byte every few minutes and each goroutine/FD is pinned indefinitely; slow readers pin response writes the same way.

Fix Wrap non-Git handlers with httpio.Protect or a global http.TimeoutHandler plus modest ReadTimeout/WriteTimeout; add MaxBytesReader to JSON bodies.

Medium severity

10 findings
M1Maintainer can flip the group Inherit flagconfirmed
internal/httpapi/api.go:630 · security · privilege escalation

The owner-only guard compares Members, Visibility, and LFS — but not Inherit, which is copied verbatim from input. A maintainer submits unchanged members with Inherit=true; the guard passes and parent members gain access to a previously isolated subgroup — a scope change the code reserves for owners.

Fix Include Inherit in the owner-only guard (require RoleOwner to change it).
M2Default LFS policy is unlimited, removing the concurrent-upload staging boundconfirmed
internal/lfs/lfs.go:369 · resource-exhaustion

The staging reservation only engages when MaximumStorageBytes > 0, but new groups default to 0. A Developer opens N concurrent PUTs each streaming up to 100 GiB into .gitone/uploads; the sha256 check runs only after the full body is written, so no valid OID is needed to fill the volume.

Fix Always take a staging reservation (treat unset quota as a finite default); cap concurrent PUTs; reject on low disk.
M3Receive-pack writes objects before validation; no GC ever reclaims orphansconfirmed
internal/githttp/handler.go:273 · resource-exhaustion

Objects are persisted before LFS-pointer/control validation and before refs are applied; on failure they remain, unreferenced. There is no GC/prune/repack anywhere. Repeatedly pushing packs that intentionally fail validation lands up to 100 GiB on disk that is never reclaimed and invisible in the ref namespace. Force-pushes leak similarly.

Fix Use git's quarantine model (stage to an alternate object dir, migrate only after validation passes); add bounded GC/prune and a per-repo git quota; lower the 100 GiB ceiling.
M4listRepositoryCommits walks the entire history on every page requestconfirmed
internal/httpapi/browser.go:932 · resource-exhaustion

The ForEach callback counts an exact total for every reachable commit, never terminates early, and ignores ctx. On a 10⁵–10⁶-commit repo, even perPage=1 forces an O(total-history) read that continues after the client disconnects; any reader can repeat it to saturate CPU/disk.

Fix Read perPage+1 for HasNext instead of an exact total (or bound the walk); honor ctx in the loop.
M5Branch compare loads both branches' full reachable-commit set into memoryconfirmed
internal/httpapi/merge.go:470 · resource-exhaustion

reachableCommits builds an in-memory hash set of every commit reachable from each tip, for base and head, with no cancellation, before the also-unbounded compareTrees. A reader hammering /compare on a large-history repo forces two full-graph traversals per request.

Fix Cap the ahead/behind computation (report >=N), use a limited revlist walk, respect ctx.
M6MR approval gate is advisory — any developer can write the target branch directlyconfirmed
internal/httpapi/merge.go:100 · security · no branch-protection concept exists

Approval/thread gating lives only inside the MR merge path. The same branch can be moved via the direct-merge endpoint (RoleDeveloper) or plain git push (RoleDeveloper), neither of which checks approvals. A developer can land their own change on main and bypass review entirely — separation of duties is unenforceable.

Fix Add protected-branch config enforced in both the direct-merge endpoint and the receive-pack authorizer; if MRs are meant to be advisory, document it.
M7Remote import has no overall size or time boundconfirmed
internal/storage/storage.go:322 · resource-exhaustion · RoleMaintainer

Mirror clone has no size cap; LFS import allows 100 GiB per object with unbounded count; only per-request dial (30 s) and header (60 s) timeouts exist, neither bounding the body, and the import runs on the request context with no overall deadline. A huge or slow-loris remote fills the disk or pins goroutines far beyond 60 s.

Fix context.WithTimeout around imports; a total-bytes budget across clone + LFS; lower the per-object cap; a global concurrent-import limit and disk preflight.
M8No graceful shutdown; SIGTERM aborts in-flight receive-packconfirmed
cmd/gitone/main.go:28 · correctness

main() calls log.Fatal(ListenAndServe()) with no signal handling and never calls Shutdown(). On docker stop/k8s termination a push is cut mid-write between object storage and ref application, leaving dangling objects and no report-status; API mutations are severed with no draining.

Fix signal.NotifyContext(SIGINT,SIGTERM), serve in a goroutine, call Shutdown(ctx) with a bounded grace period — mirror the runner.
M9Containers run as root; base images pinned only by tagconfirmed
Dockerfile:17 · Dockerfile.runner · docker-compose.yml · security

Neither Dockerfile declares USER, so both run as UID 0; base images use mutable tags; the runner mounts /var/run/docker.sock as root (root-equivalent on the host). Any RCE/traversal bug yields root with a root-owned /data bind mount; a repointed upstream tag is pulled silently.

Fix Non-root USER with /data owned accordingly; pin bases by sha256 digest; drop docker.sock from the server; read-only rootfs / no-new-privileges.
M10No Content-Security-Policy or security headers on UI/APIconfirmed
internal/webui/webui.go:35 · security · UI renders user markdown/blobs

Responses ship only Content-Type and Cache-Control; DOMPurify at the sink (app.ts:4652) is the sole XSS barrier. A single DOMPurify bypass, missed innerHTML sink, or dependency regression becomes script execution in the authenticated origin with no CSP backstop; missing frame-ancestors allows clickjacking of merge/settings actions.

Fix Header middleware: strict CSP, nosniff, Referrer-Policy: no-referrer, X-Frame-Options: DENY, HSTS over HTTPS.

Low severity & info

14 low · 1 info
L1Repository file-path parameter has no depth or length limitconfirmed
internal/httpapi/browser.go:1044 · resource-exhaustion

cleanRepositoryPath rejects traversal/NUL but not length or component count; tree-edit helpers recurse and write a tree object per component. A ~10⁵-component path creates ~10⁵ nested tree objects in one call, with attacker-controlled recursion depth. Fix bound length & component count; consider iterative rewrite.

L2Body slowloris: sliding idle deadline has no absolute cap or connection limitplausible
internal/httpio/httpio.go:21 · resource-exhaustion

The deadline resets on every Read, bounding one blocked read but not total duration; no connection cap. A byte every <30 s holds a goroutine/socket/temp file indefinitely — tempered by auth on heavy paths and Go's tolerance for idle conns. Fix absolute per-request deadline / min-throughput; bound in-flight transfers.

L3Server sets no WriteTimeout or overall request timeoutconfirmed
cmd/gitone/main.go:99 · resource-exhaustion · backstop for H2/M4/M5

No WriteTimeout or per-handler timeout means CPU-bound handlers can't be aborted and slow readers pin connections. Fix add WriteTimeout + http.TimeoutHandler (keep streaming on the sliding-deadline path).

L4Stateless sessions can't be revoked; logout leaves signed cookies validconfirmed
internal/auth/session.go:161 · security

Self-contained securecookies with no server store; a captured cookie stays valid until MaxAge (12 h) despite logout, password change, or account disable. (Authorization changes do apply immediately — the cookie carries identity only.) Fix per-user token version checked against a server counter, or shorter MaxAge; document non-revocability.

L5Internal go-git error strings echoed to clientsconfirmed
internal/httpapi/browser.go:1010 · security · information disclosure

Handlers pass raw errors to huma.Error*, serializing object IDs, pack/loose state, and filesystem messages into the response body for low-trust callers. Fix log server-side, return generic messages for 5xx/not-found on low-trust endpoints.

L6One bad review record disables all MR listing & mutations repo-wideconfirmed
internal/review/store.go:437 · correctness / availability

listDirectory aborts on the first parse/validate failure, and Create/Update re-list for a duplicate-branch scan — so one corrupt file breaks List, Create, and every open-MR mutation. DisallowUnknownFields also makes newer records unreadable to older binaries. Fix skip-and-log bad records; gate strict decoding behind a schema version.

L7Review writes & directory renames aren't durably fsyncedconfirmed
internal/review/store.go:555 · correctness

The temp file is fsynced but the containing directory is never fsynced after rename. On power loss a lost rename silently reverts an approval/comment/close the API already confirmed; only the merge-in-progress case is reconciled. Fix fsync the parent directory after rename; document the durability contract.

L8Group LFS usage recomputed with a full filesystem walk per requestconfirmed
internal/lfs/lfs.go:626 · performance · only when a quota is configured

groupStorageUsage walks the whole objects tree (twice per PUT, under the exclusive group lock) with no cached accounting — O(objects) per request, serializing concurrent PUTs. Fix incremental per-group byte counter updated under the existing lock.

L9Token-key enumeration via Argon2id timing oracleconfirmed
internal/auth/auth.go:62 · security · leaks non-secret labels

The short-circuiting token.Key != user check gates the expensive Argon2id, so a matching key is measurably slower — a clean latency oracle (no LDAP round-trip for non-email keys) revealing configured automation token identifiers. Fix dummy Argon2id on no-match; subtle.ConstantTimeCompare for keys.

L10LDAP canonical identity case-normalized only for mailconfirmed
internal/auth/ldap.go:232 · correctness · config trap

For non-mail attributes (uid, sAMAccountName) the directory value is used verbatim as Principal.Name, while member lookups are exact case-sensitive maps — so Alice vs recorded alice misses (fail-closed but confusing). Fix one documented normalization for all attributes; normalize member keys identically.

L11Session cookie Secure off by default (http public-url default)confirmed
internal/auth/session.go:38 · security

Secure keys off the -public-url scheme, which defaults to http://localhost:8080, and GITONE_SESSION_SECURE=false can force it off. A TLS-terminating proxy left on the http default plus a downgrade request leaks the cookie. Fix default Secure true; refuse false with an https public-url; warn on scheme mismatch.

L12Dead root ldap.go carries injection & TLS-skip patternsconfirmed
ldap.go:1 · maintainability · //go:build ignore, foreign imports

A build-excluded copy from another project with an unescaped fmt.Sprintf LDAP filter, sitting misleadingly beside the real, correct authenticator. Not exploitable, but a refactor trap. Fix delete it (or move reference material out of the module root, clearly marked).

L13Stale foreign source file & unused config packageconfirmed
ldap.go:1 · internal/config · maintainability

The same file is a divergent second LDAP implementation, and internal/config is referenced only by tests while the server configures via flags — dead code obscuring how the server is configured. Fix consolidate to one LDAP implementation; remove or wire in internal/config.

L14docker-compose ships insecure defaultsconfirmed
docker-compose.yml:13 · security

LDAP_SKIP_TLS_VERIFY=true over the password-bearing bind, a published default GITONE_RUNNER_TOKEN, and a host /data mount — with no in-file warning these are dev-only. Dangerous if copied toward production. Fix split a labeled dev compose; require LDAP TLS; require a non-default token; fail fast on the known dev value.

I1LDAP_SKIP_TLS_VERIFY disables cert verification for credential bindsconfirmed
internal/auth/ldap.go:117 · security · info · operator footgun

When set, disables cert validation (defeating ServerName pinning) for ldaps:// and StartTLS while the plaintext simple bind sends the user password — MITM credential capture. Fix treat as strictly dev: warn at startup, forbid with an https public-url, steer to LDAP_CA_FILE.

04 — Cross-cutting themes

The patterns beneath the list
limits

Missing resource limits is the defining pattern. Over half the findings (H1–H5, M2–M5, M7, L1–L3, L8) are the same story — no cap on time, size, count, concurrency, or growth. Every unbounded quantity ends at the same shared single process.

timeouts

No wall-clock request budget anywhere. main.go:99 recurs: no ReadTimeout/WriteTimeout/TimeoutHandler, and the expensive handlers ignore ctx. Timeouts plus a connection cap are the single backstop that would blunt H2, H5, M4, M5, L2, and L3 at once.

blast radius

Single-process, single-writer. One OOM, one filled disk, one held catalog lock, or one abrupt SIGTERM affects every repo on the storage root. The in-memory lockmgr.Process is also the ceiling on HA and zero-downtime deploys.

authz gaps

Gates that aren't authoritative. The MR approval machinery (M6) and the owner-only guard (M1) are carefully written but bypassable — no protected-branch concept, and the guard omits Inherit. The controls exist; their coverage is incomplete.

write-first

Optimistic write paths. Receive-pack persists before validating (M3), review writes skip directory fsync (L7), and one bad record bricks the MR store (L6) — a recurring "assume success, crash on failure" theme distinct from the DoS cluster.

ops

Deployment hardening is unfinished. Root containers, tag-pinned bases (M9), no security headers (M10), no graceful shutdown (M8), insecure compose/LDAP defaults (L14, I1): application security matured faster than operational packaging.

06 — Suggested roadmap

A sequence, not a backlog
First

Stop the bleeding — harden the single process

  1. Request deadlines, WriteTimeout, TimeoutHandler, MaxBytesReader, connection cap (H5, L2, L3; blunts H2/M4/M5)
  2. Auth rate limiting + Argon2id concurrency semaphore (H1)
  3. Cap diff/compare output; make history/reachable walks honor ctx (H2, M4, M5)
  4. Fix the runner claim to not hold the exclusive lock during scans; add job pruning (H3)
  5. Sandbox build containers: --network none + cgroup limits + non-root (H4)
  6. Graceful shutdown, security headers, /readyz (M8, M10)
Next

Close authorization & correctness gaps, get observable

  1. Protected branches in both direct-merge and receive-pack (M6); include Inherit in the owner guard (M1)
  2. Always reserve LFS staging (M2); quarantine receive-pack objects + GC + git quotas (M3); bound imports (M7)
  3. Robustness: fsync review dirs (L7), skip-and-log bad records (L6), bound file-path depth (L1)
  4. Observability: structured logging + request IDs + panic recovery, Prometheus, audit logging
  5. Container/image hardening (M9), personal access tokens, credential-hygiene fixes (L4, L5, L9, L11, L14, I1)
  6. Delete dead ldap.go / internal/config leftovers (L12, L13)
Later

Grow the product & remove the scaling ceiling

  1. Cross-process locking (unlocks HA & zero-downtime), plus Helm chart and backup/restore
  2. Feature depth: issues, SSH transport, protected-branch-driven CI gating, webhooks, email notifications
  3. Strategic bets: OCI registry, code search, distributed tracing, and the rounding-out security/DX features
